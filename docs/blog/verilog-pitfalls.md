# Verilog 里那些「能编译但仿真全是 X」的坑

Verilog 最让人难受的一点是：**它对你犯的错太宽容了**。未声明的标识符、漏掉的端口、位宽不匹配，很多时候都不报错，而是悄悄变成高阻 `Z`，然后在仿真里到处传染成 `X`。

下面几个坑我反复遇到过，记下来。

## 1. 未声明标识符 = 隐式 1 位 wire

```verilog
// 想写 bq，手滑写成了 bQ
assign result = bQ + 1;
```

`bQ` 没有声明，Verilog 会把它当成一根隐式的 1 位 wire，值为 `Z`。编译不报错（除非开了严格检查），仿真里 `result` 直接变 X。

**对策**：打开 `default_nettype none`，或者至少在写端口连接前 grep 一下名字。

## 2. 端口位宽不匹配，高位悬空

```verilog
// 子模块端口是 [7:0]
wire [3:0] data;
my_module u0 (.data(data));   // 高 4 位悬空
```

父模块的 wire 比子模块端口窄时，高位会变成 `Z`。仿真表现是「某些地址读出来全是 X」，非常难往端口连接上想。

**对策**：所有跨模块的连接都显式写位宽，别依赖默认值。

## 3. 非阻塞赋值带来的「晚一拍」

```verilog
always @(posedge clk) begin
  addr  <= cnt;
  data  <= mem[cnt];
  we    <= 1'b1;
end
```

这里 `addr` 和 `data` 用的是上一拍的值，最后一个元素永远写不进去。递增计数器时特别容易踩。

**对策**：地址和数据用组合逻辑的 `wire`，只有写使能打拍：

```verilog
wire [12:0] a_addr = cnt[12:0];
wire [31:0] a_data = mem[cnt];
always @(posedge clk) begin
  if (cnt_done) we <= 1'b0;
  else          we <= 1'b1;
end
```

## 4. FIFO / RAM 扩容后越界

读 4 字节宽的数据时写 `buf[addr + 3]`，最后一次读会越界 3 个位置，返回 X。即使后面用 mask 把结果屏蔽掉，**未初始化区域的 X 仍会沿着 `p_rd_data4` 传染下去**。

**对策**：数组多开几个元素的余量，或者对读地址做饱和处理。

## 5. 多周期子模块，不能假设一次 start 就全算完

比如 softmax 一次处理一行，顶层状态机必须显式循环，等子模块的 `done` 再进下一步。否则你只是发出了第一个 `start`，剩余的行根本没算，输出自然是 X。

## 6. 状态数超过 2^N

```verilog
reg [1:0] state;   // 最多 4 个状态
localparam S_WAIT = 2'd0, S_RUN = 2'd1, S_DONE = 2'd2, S_ERR = 2'd3;
// 后来加了个 S_RECOVER = 2'd4 —— 直接溢出
```

**对策**：加状态时先确认位宽，或者干脆用 `$clog2` 定义。

## 一条经验

> 编译 0 错误、引脚分配正确、能跑出部分正确结果，都**不能**证明设计是对的。

遇到「一片 X」的时候，最有效的做法通常不是盯着波形猜，而是：

1. 从最上游的模块开始，检查端口有没有接上
2. 检查所有数组和存储有没有被初始化
3. 检查是否存在位宽不匹配
4. 再去看时序

大部分「莫名其妙全是 X」的问题，都死在前三步。
