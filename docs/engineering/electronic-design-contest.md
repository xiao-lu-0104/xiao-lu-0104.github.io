# 2026 电赛 G 题：基于 Zynq 的频谱分析与参数测量

## 题目与方案

G 题的核心是信号参数测量：在一段较宽的频率范围内，测出信号的频率、幅值、相位，并识别其中的谐波成分。

单靠 MCU 做 FFT 有两个绕不开的问题：采样率上不去，频率分辨率也不够。所以整体方案拆成两半：

- **PL（FPGA）**：负责高速采集。ADC 数据直接写进 AXI BRAM，采满一帧后产生中断
- **PS（Cortex-A9）**：负责分析。读 BRAM、做周期截取、FFT、CZT，最后把结果推到串口屏

这样 PL 只管确定性时序，PS 专心做算法，两边通过 BRAM 和一组自定义寄存器交互。

## 系统架构

```text
ADC ──▶ PL 采集逻辑 ──▶ AXI BRAM（8192 点）
                            │
                            │ PL 中断
                            ▼
                   PS：周期截取 → FFT → CZT → 参数计算
                            │
                            ▼
                       串口屏（921600）
```

| 参数 | 值 |
| --- | --- |
| 采样率 | 8.192 MHz |
| 时域采样点 | 8192 |
| FFT 点数 | 16384 |
| FFT 频率间隔 | 500 Hz |
| CZT 输入点数 / 输出频点 | 4096 / 1024 |
| CZT 分析带宽 | 1023 Hz（约 1 Hz 一个频点）|

## 关键实现

### 1. 采集与中断

PS 侧通过自定义 IP 输出一个 50 ms 的「按键脉冲」启动采集，PL 采满 8192 点后拉中断。中断服务函数里只做两件事：置标志、关中断，真正的处理放在主循环：

```c
static void PL_IrqHandler(void *CallbackRef)
{
    XScuGic_Disable(&ScuGic, PL_IRQ_ID);
    g_irq_count++;
    g_capture_done = 1;
}
```

主循环里处理完一帧再重新 `XScuGic_Enable`，避免数据还没读完就被下一帧覆盖。

### 2. 周期截取

FFT 最怕的不是分辨率不够，而是**非整周期截断**带来的频谱泄漏。解决办法是先从时域数据里找出一个完整周期，再拿这个周期做变换。

实现上用归一化自相关找周期，峰值位置再用抛物线插值修正到亚采样点精度，频率由 `fs / period` 得到：

```c
ret = pc_extract(g_ad_cache_u16,
                 AD_SAMPLE_NUM,
                 g_ad_period_u16,
                 PERIOD_CUT_DST_CAP,
                 NULL,
                 &g_period_result);
```

返回结果里带一个 `quality`（归一化相关度），低于 0.5 就认为信号不周期，不采信这个结果。

### 3. FFT 粗测

先用 16384 点 FFT 找到能量最强的几个峰，跳过直流分量，用 100 Hz 的容差判断它是不是基波的整数倍谐波。FFT 只负责「找到大概在哪」，精度交给下一步。

### 4. CZT 细化

FFT 的频率间隔被 `fs/N` 锁死，这里就是 500 Hz。CZT（Chirp-Z 变换）可以在指定频段上取任意多个等间距频点：

```c
czt_execute(&g_czt_ctx, g_czt_x, CZT_N, SAMPLE_RATE_HZ,
            f0, CZT_SPAN_HZ, CZT_M,
            g_czt_freq, g_czt_mag, g_czt_phase);
```

在基波附近取 1023 Hz 带宽、1024 个频点，等效分辨率约 1 Hz。幅值和相位都从 CZT 结果里取。

::: tip 一个容易误解的点
CZT 提高的是**频点密度**，不是**频率分辨能力**。两个靠得很近的频率能不能分开，仍然由观测时长 `N/fs` 决定，CZT 不能突破这个限制。
:::

### 5. 幅值修正

CZT 前加了 Hann 窗，输出幅值要除以窗函数的相干增益才能还原真实峰值。另外还做了三件事：

- 峰值附近三点抛物线插值，减少栅栏效应
- 谐波存在时，Vpp 和 RMS 乘 1.034 的经验修正系数
- 用识别出的各次谐波合成一个完整周期，反算 Vpp 和 RMS 做交叉验证

## 踩过的坑

::: warning 自相关不能按重叠长度归一化
最初用 `r/(n-lag)` 归一化，lag 越大方差越大，结果把 2T、3T 误判成周期。改成 Pearson 形式（两段各自用自己的能量归一）之后才稳定。
:::

::: warning AD BRAM 的数据格式
PL 写进 BRAM 的可能是完整 32 位有符号数，也可能只是低 16 位。读的时候必须和 PL 侧对齐，否则波形看起来「有数据」但幅值完全不对。代码里用 `AD_BRAM_DATA_LOW16_SIGNED` 显式切换。
:::

::: warning 串口屏和调试串口要分开
Zynq 的 UART0 和 UART1 一个是调试口、一个是屏幕口，一开始混用，导致屏幕收不到指令。后来固定 UART0 接屏、UART1 打日志。
:::

## 结果

系统支持波形、频谱、幅值三种显示模式，能给出基波频率、各次谐波的幅值与相位，并在谐波存在时对时域测量值做修正。

## 复盘

- 高速采集交给 PL、算法交给 PS，是这类题目最省心的分工
- 测频、测幅、测相位是三件不同的事，各自的最优算法不一样，不能指望一次 FFT 全解决
- 参数化很重要：采样率、点数、CZT 带宽全写成宏，改一个数就能重新扫参数
- 代码里那些「为什么这么写」的注释，调试时救了自己很多次
