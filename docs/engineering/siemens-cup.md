# 西门子杯：六轴运动控制系统的设计与调试

## 项目背景

比赛要求在一个小型自动化工作站上完成「上料—搬运—定位—装配」的流程，六个轴需要按工艺节拍协同动作，同时保证定位精度和整线节拍。我负责的是控制器程序、轨迹规划和 HMI 三块。

## 系统结构

| 模块 | 选型 | 作用 |
| --- | --- | --- |
| 控制器 | S7-1200 | 逻辑控制、轴运动控制 |
| 驱动 | SINAMICS V90 + 伺服电机 | 位置 / 速度闭环 |
| 通信 | PROFINET | 控制器与驱动器、远程 IO |
| 交互 | 精简 HMI 面板 | 参数设置、状态监控、报警 |

## 关键实现

### 1. 运动控制

每个轴用工艺对象（Technology Object）组态，运动指令通过 `MC_MoveAbsolute` / `MC_MoveRelative` 下发。难点不在单轴，而在**多轴联动的时序**：

- 用状态机把「等待到位 → 夹紧 → 抬起 → 平移」串起来
- 每个动作都带超时监控，避免某个轴卡住导致整线死等
- 急停后所有轴进入受控停止，而不是直接断使能

### 2. 轨迹平滑

直接给梯形速度曲线时，机械结构在起停瞬间抖动明显。后来改成 S 曲线加减速，把加速度的变化率也限制住，抖动基本消失。

```text
速度
  ▲        ┌──────────┐
  │      ╱            ╲
  │    ╱                ╲
  └──┴────────────────────┴──▶ 时间
     加速   匀速        减速
```

### 3. HMI

用画面切换 + 报警记录做了最基础的一套。踩过的坑是**变量刷新周期**：HMI 读 PLC 变量太快会把通信负载打满，太慢又显得卡。最后按变量重要性分组，状态类 100 ms，参数类 500 ms。

## 踩过的坑

::: warning 编码器方向
某一版程序里两个轴的方向定义相反，单轴调试都正常，联动时轨迹直接反了。后来统一在驱动器侧做方向取反，程序里不再处理符号。
:::

::: warning 通信中断恢复
PROFINET 掉线后，PLC 里保留的还是掉线前的目标位置。恢复通信后如果直接继续执行，轴会突然冲过去。加了一步「重新同步当前位置」才解决。
:::

## 结果

工作站完成了完整工艺流程，节拍满足要求。比起最后的名次，我觉得更有价值的是第一次完整地做了一遍「机械—电气—控制—交互」的联调。
