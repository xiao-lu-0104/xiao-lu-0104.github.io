# 一生一芯：从零设计一颗 RISC-V 处理器

## 这段经历是什么

「一生一芯」要求参与者从指令集规范出发，独立完成一颗 RISC-V 处理器的设计、验证，并走完从 RTL 到流片的全部流程。我完成的是 E 阶段：处理器核 + SoC 集成 + 基础软件运行。

## 我做了什么

### 1. 处理器核

- RV32I 基础指令 + 部分 M 扩展
- 五级流水线：IF / ID / EX / MEM / WB
- 前递（forwarding）+ 分支预测（静态）
- 中断与异常处理

流水线里最容易出错的是**控制冒险**和**数据冒险**的边界情况。我的做法是把每条指令在不同阶段的行为列成表格，再逐格检查。

### 2. 总线与 SoC

核通过 AXI 接入 SoC，外设包括 UART、GPIO、定时器和一段片上 RAM。

```text
┌─────────┐    AXI     ┌──────────┐
│  CPU    │◀──────────▶│  互连    │
└─────────┘            └────┬─────┘
                            │
          ┌─────────────────┼─────────────────┐
          ▼                 ▼                 ▼
      ┌───────┐        ┌────────┐        ┌────────┐
      │ UART  │        │  GPIO  │        │  RAM   │
      └───────┘        └────────┘        └────────┘
```

### 3. 验证

- **Difftest**：把每条指令执行后的寄存器状态和参考模型（NEMU）逐条比对
- 单元测试：给每个模块写定向测试
- 随机测试：生成随机指令序列，跑长时间回归

Difftest 救了我很多次——有些 bug 在裸跑时只是结果偶尔不对，一旦逐条比对就立刻定位到具体指令。

## 印象最深的几个坑

::: warning 位宽不匹配
父模块的 wire 比子模块端口窄，高位直接悬空成 `Z`。仿真里表现为「某些地址读出来全是 X」，查了很久才定位到端口连接。
:::

::: warning 状态机位宽
状态数超过了 `2^N`，新加的状态直接被综合工具截断。改成 `localparam` + 显式位宽后再没出过问题。
:::

::: warning 「能跑」不等于「对」
最早只验证了程序能打印 `Hello`，就以为处理器没问题。后来加了完整回归才发现移位指令的边界情况有错。
:::

## 收获

- 学会了「先写参考模型，再做实现」的验证思路
- 理解了流水线设计里各种冒险的真实代价
- 对「从 RTL 到流片」的完整链路有了概念

这段经历基本决定了后来我做硬件相关工作的方式：**先想清楚数据怎么流，再想代码怎么写**。
